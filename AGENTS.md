## Project rules (Wardrobe)

These rules apply to everyone working in this repository, human or agent.

- No AI or tool attribution anywhere: no co-author trailers in commits, no "generated by" text in code, docs or PRs.
- Keep the docs current. `HANDOFF.md` gets a dated entry every phase (state, decisions, checks actually run with timestamps, migration and deploy state, live checks pending, next steps with Beads ids). New decisions go into `DECISIONS.md` as D-numbered entries. `README.md` stays a stable reference.
- Track tasks in Beads (`bd prime` for the workflow, `bd ready` for open work). Do not write markdown TODO lists or checklists.
- Phase gate: `pnpm typecheck && pnpm lint && pnpm test && pnpm build`. A phase is not done until all four pass.
- Never commit `.env*` files except `.env.example`. Never print or echo secrets.
- Deploy only when the owner asks.
- Validate UI changes in a visible browser window, not only headless.
- Report only checks that were actually run, with their results.
- Cache Components convention: each page is a static shell. Session, cookies, `searchParams`, route `params` and DB reads go in async child components inside `<Suspense>`; pass the `params` promise down and await it inside the child. No `dynamic` or `runtime` segment exports.
- Every Server Action, Route Handler and server read function calls the DAL session check (`requireSession()`). `proxy.ts` is only an optimistic first filter.
- tsx scripts run with `tsx --conditions=react-server` so `server-only` imports resolve.
- Every server Blob call (`put`, `del`, `head`) passes `token: BLOB_READ_WRITE_TOKEN` explicitly.
- Structured-output schemas must not contain keys named `reasoning`, `thinking` or `thought`; use `why` or `reason`.
- shadcn components here use Base UI: compose with the `render` prop, never `asChild`.
